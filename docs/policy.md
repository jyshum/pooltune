# Local policy compiler and classifier

`policy.Compile(candidate, guardrails, registry)` validates a candidate against the current trusted revision and guardrail version. It returns immutable lookup tables or an error. The caller must keep the last stable compiled policy when compilation fails. This package does not publish a revision or perform admission.

The trusted registry defines each opaque workload ID, exact target/path/principal selector, approved classes, locked rule, tenant trust, weight range, maximum queue wait, maximum concurrency, and whether blocking is authorized. REST selectors also include an exact canonical method and route. An identity default omits method and route. PostgreSQL role mappings use the target, path and authenticated principal. SQL fingerprints, comments, `application_name`, headers and the request's `Workload` hint do not select a workload.

The candidate can select classes through rules and choose three positive integer shared class weights, per-workload queue count, queue wait, concurrency cap, and reserve fraction within approved bounds. The registry supplies an approved normal fallback with its own count, wait and cap. Locked registry rules apply even when omitted from the candidate. A candidate rule that changes a locked class is rejected. Duplicate exact selectors, duplicate rule IDs, unknown workload references, stale versions and stale predecessors are rejected. Schema version `1` is supported. The candidate cannot define selectors or trusted identities.

For an existing revision, guardrails carry the matching immutable `CurrentPolicy` and `MaxChangedEntries`. Compilation rejects a missing or stale baseline. It counts one changed entry for each workload whose effective class, queue wait, queue count, cap or blocked flag differs, plus one for each changed class weight and one for a changed reserve fraction. Descriptions and rule ID-only edits do not consume this count. The initial revision may have an empty predecessor and no baseline; setup approval owns that bootstrap policy.

`policy.Classify(compiled, context)` uses the exact selector, then the approved identity default, then a single normal overflow group. It retains the matched rule and policy revision. Unknown identities cannot acquire a critical class or create unbounded workload buckets. The ingress adapter must authenticate the principal, parse canonical routes, establish `TrustedTenant` from an approved claim source and reject protocol/authentication failures before classification. When tenant trust is approved, fairness keys include target, path, principal and tenant. They never merge different principals with the same tenant string. Tenant cardinality limits belong to the traffic scheduler.

The classification carries queue count, concurrency cap, blocked state and queue deadline. Shared class weights are read once through `CompiledPolicy.ClassWeights()` by the scheduler. The deadline is the earlier of the original client deadline and the approved maximum wait from classification time. A blocked workload has an explicit operator authorization and zero queue/cap; the scheduler must reject it. The overflow group uses the registry's bounded normal fallback. A nil compiled policy returns a blocked classification. Admission, in-flight PostgreSQL transaction binding, capacity math and cohort selection are separate tasks. The executable continues to serve health checks only.
