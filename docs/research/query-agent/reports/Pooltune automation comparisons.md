## Cast AI separates assessment from active optimization

Cast AI’s Kubernetes assessment agent reads cluster resources and sends snapshots. Enabling automation adds a controller with permissions to modify or delete nodes and evict pods. This is real infrastructure authority. Historical public controller code implements typed actions, concurrency limits, and success/error acknowledgements. The repository is now archived, so it supports the existence of concrete automation without establishing today’s complete implementation. Neither the permissions nor that code establishes that an LLM chooses every action. ([Permissions](https://docs.cast.ai/docs/kubernetes-permissions), [controller source and archive notice](https://github.com/castai/cluster-controller))

Database Optimizer requires a more precise distinction. **Performance Advisor collects evidence and recommends changes without modifying schema.** It examines query statistics, table/index metadata, and column statistics. It prioritizes index recommendations by reclaimable database time and uses an LLM plus heuristics for query rewrites. Recommendations require human review, and the advisor can work without proxying application traffic. This directly overlaps with Pooltune’s intended diagnosis work. Predicted improvements and explain-plan comparisons support investigation; they do not establish measured production improvement after a repair. ([Performance Advisor](https://docs.cast.ai/docs/dbo-performance-advisor))

The separate Rust proxy runs in customer Kubernetes or Amazon ECS and requires an application connection-string change. It provides caching and connection pooling; writes pass through, while observed writes inform cache invalidation. The optional advisor’s read-only identity is separate from ordinary application connectivity through the proxy. Cast documents these capabilities as production features in DBO 2.0. Thus DBO is adjacent to Pooltune, but its documented runtime intervention mainly changes traffic serving. Pooltune’s selected design preserves the existing application connection path and requires no customer-installed proxy. ([Architecture](https://docs.cast.ai/docs/dbo-how-does-it-work), [permissions](https://docs.cast.ai/docs/dbo-access-requirements-and-permissions), [release notes](https://docs.cast.ai/changelog/august-2026), [Pooltune plan](</Users/jshum/Desktop/code-folders/pooltune-learning/docs/product/query-performance-v1.md>))

## Five lessons fit Pooltune’s existing scope

**Separate observation from authority.** Cast’s assessment-to-automation progression is useful. Pooltune should distinguish inspection, experiments, and execution grants. Its accepted Go tools must enforce target identity, fresh preconditions, permitted effects, and resource limits. The model’s recommendation cannot create permission. ([Cast permissions](https://docs.cast.ai/docs/kubernetes-permissions), [accepted responsibilities](</Users/jshum/Desktop/code-folders/pooltune-learning/docs/product/query-performance-v1.md>))

**Show estimates separately from outcomes.** Cast starts proxied databases in passthrough mode to gather a baseline and project caching benefit. Pooltune can borrow that clarity without adopting caching: label planner estimates, observed baselines, and measured outcomes separately. Reuse sufficiently fresh existing evidence; request another experiment only when it answers a decision-changing gap. ([DBO connection flow](https://docs.cast.ai/docs/dbo-connecting-client-applications), [evidence policy](</Users/jshum/Desktop/code-folders/pooltune-learning/docs/product/query-performance-v1.md>))

**Turn checklist topics into evidence questions.** VoltAgent’s breadth helps avoid jumping to indexes for every slowdown. Each question should identify its evidence source and the decision it affects. Recognizing an application or infrastructure cause must remain possible even when repairing it is outside Pooltune’s authority. ([Investigation checklist](https://github.com/VoltAgent/awesome-claude-code-subagents/blob/8ce183f5900c718e5a139982c910039d54017fbd/categories/05-data-ai/database-optimizer.md))

**Make recovery and history explicit.** Cast exposes configuration audit history and controls to pause caching. Pooltune needs durable action records, reconciliation before retrying uncertain operations, and repair-specific recovery. A stop control prevents further work; it cannot undo completed `ANALYZE` or `VACUUM`. ([Audit log](https://docs.cast.ai/docs/dbo-audit-log), [pause controls](https://docs.cast.ai/docs/dbo-pause-dbo-for-troubleshooting), [recovery requirements](</Users/jshum/Desktop/code-folders/pooltune-learning/docs/product/query-performance-v1.md>))

**Evaluate justified inaction as well as successful repairs.** Test healthy databases, misleading symptoms, incomplete evidence, failed operations, and repeat runs. Compare completed work, latency, errors, write overhead, and resource costs. Neither an arbitrary index-usage target nor a successful SQL command establishes customer value. ([Pooltune success criteria](</Users/jshum/Desktop/code-folders/pooltune-learning/docs/product/query-performance-v1.md>))

## Pooltune’s distinction must survive implementation

The accepted scope remains nonunique indexes, targeted `ANALYZE`, richer statistics, bounded cleanup, enrolled function `work_mem`, and enrolled Cron shifts. Go, one TypeScript/LangGraph investigator, and owned PostgreSQL are implementation choices supporting that scope. These comparisons justify improving tool contracts and evaluation, not adding proxies, application rewrites, or infrastructure purchasing. The opportunity is to prove that this narrow hosted service repeatedly makes warranted repairs and leaves databases alone when it should.
